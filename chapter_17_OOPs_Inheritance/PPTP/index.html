164 - Inheritance Basics

164_Inheritance.js Single_Inheritance extends

Inheritance lets a child class reuse methods from a parent class using extends. LoginPage inherits open() and close() from BasePage without defining them.

class BasePage {
    constructor(pageName) {
        this.pageName = pageName;
    }
    open() { console.log("Opening the page"); }
    close() { console.log("Closing the page"); }
}

class LoginPage extends BasePage { }

let page = new LoginPage();
page.open();  // inherited from BasePage
page.close(); // inherited from BasePage

165 - super() Keyword

165_SI.js super()

When a child class has its own constructor, super() calls the parent constructor. super.methodName() calls a parent method — essential for extending behavior without replacing it.

class Animal {
    constructor(name) {
        this.name = name;
    }
    eat() { console.log(this.name + " is eating"); }
}

class Dog extends Animal {
    constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
    }
}

166 - Method Overriding

166_Method_Overriding.js Override

When a child class defines the same method as the parent, the child's version is used. The object's type determines which method runs — this is polymorphism in action.

class BaseTest {
    setup() { console.log("Base: open browser"); }
}

class APITest extends BaseTest {
    setup() { console.log("APITest: open browser"); }
}

let test = new APITest();
test.setup(); // "APITest: open browser" — child wins

167 - super.method() Call

167_MO_IQ.js super.method()

Using super.setup() inside a child's override to call the parent version first, then add extra behavior. This extends rather than replaces the parent method.

class BaseTest {
    setup() { console.log("Base: open browser"); }
    teardown() { console.log("Base: close browser"); }
}

class UITest extends BaseTest {
    setup() {
        super.setup(); // call parent first
        console.log("UI: maximize window");
    }
    teardown() {
        console.log("UI: take screenshot");
        super.teardown(); // call parent last
    }
}

168 - Polymorphism

168_MO_BIG.js Polymorphism

Multiple child classes override the same execute() method. You can loop through different test types and call the same method — each object behaves differently based on its class.

class TestCase {
    execute() { console.log("Running generic test"); }
}

class UnitTest extends TestCase {
    execute() { console.log("Running unit test"); }
}

class APITest extends TestCase {
    execute() { console.log("Running API test"); }
}

class E2ETest extends TestCase {
    execute() { console.log("Running E2E test"); }
}

169 - Page Object Pattern

169_PageObject.js Page Object Model

The POM pattern: BasePage defines a generic verify(), then LoginPage and DashboardPage each override it with page-specific verification logic — a core SDET design pattern.

class BasePage {
    verify() { console.log("Verifying base page"); }
}

class LoginPage extends BasePage {
    verify() {
        console.log("Verify: username field exists");
        console.log("Verify: password field exists");
        console.log("Verify: login button is visible");
    }
}

class DashboardPage extends BasePage {
    verify() {
        console.log("Verify: welcome message shown");
        console.log("Verify: sidebar menu loaded");
    }
}

170 - Report Override

170_RO.js Report Formats

A Report base class with HTML, JSON, and Text subclasses each overriding generate() — same interface, different output formats. Maps to Playwright's reporter system.

class Report {
    generate(data) { console.log("Raw: " + data); }
}

class HTMLReport extends Report {
    generate(data) {
        console.log("<html><body>" + data + "</body></html>");
    }
}

class JSONReport extends Report {
    generate(data) {
        console.log('{\"report\": \"' + data + '\"}');
    }
}

171 - Multi-Level Inheritance

171_MI.js Multi_Level_Inheritance A → B → C

Multi-level: BasePage → AuthPage → AdminPage. Each level adds new capabilities while inheriting everything from above. Like Grandfather → Father → Son.

class BasePage {
    constructor(name) { this.name = name; }
    open() { console.log("[OPEN] " + this.name); }
}

class AuthPage extends BasePage {
    login(user) { console.log("[LOGIN] " + user); }
}

class AdminPage extends AuthPage {
    manage() { console.log("[MANAGE] admin panel"); }
}

// AdminPage has open(), login(), AND manage()

172 - Multiple Inheritance (Mixins)

172.js Multiple_Inheritance Mixins

JavaScript doesn't support class C extends A, B. Instead, use the Mixin pattern — functions that take a class and return a new class with added behavior. Compose abilities like Lego blocks.

// class C extends A, B { }  ❌ SyntaxError

let LoggerMixin = function(Base) {
    return class extends Base {
        log(msg) { console.log("[Log] " + msg); }
    };
};

let ScreenshotMixin = function(Base) {
    return class extends Base {
        takeScreenshot() { console.log("[SCREENSHOT] captured"); }
    };
};

// Compose: Base + Logger + Screenshot
class TestPage extends ScreenshotMixin(LoggerMixin(Object)) { }

173 - Exporting Classes

Basepage.js / LoginPage.js / 173_Test_2.js Exporting_Class Module Classes

Splitting classes across files using export/import. BasePage is exported, LoginPage imports and extends it, and the test file imports LoginPage — real project structure.

// Basepage.js
export class BasePage {
    constructor(name) { this.name = name; }
    open() { console.log("Opening " + this.name); }
}

// LoginPage.js
import { BasePage } from "./Basepage.js";
export class LoginPage extends BasePage {
    login(user) { console.log(user + " logged in"); }
}

// 173_Test_2.js
import { LoginPage } from "./LoginPage.js";
let page = new LoginPage();
page.open();
page.login("admin");

174 - Hierarchical Inheritance

174_HI.js Hierarchial_Inheritance One Parent, Many Children

Hierarchical inheritance: one parent class with multiple independent children. Each child inherits from the same parent but is independent of its siblings — like multiple page classes extending BasePage.

class Father { }

class Son1 extends Father { }
class Son2 extends Father { }

// Both Son1 and Son2 inherit from Father
// But Son1 and Son2 are independent of each other
