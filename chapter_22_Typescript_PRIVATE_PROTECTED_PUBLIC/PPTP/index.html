200 - Public / Private / Protected

200_PRIVATE_PUBLIC_PROTECTED.ts Access Control

TypeScript's three access modifiers: public (accessible everywhere), private (only within the class), and protected (within the class and its subclasses).

class APIClient {
    public baseURL: string;
    private apiKey: string;
    protected timeout: number;

    constructor(baseURL: string, apiKey: string, timeout: number) {
        this.baseURL = baseURL;
        this.apiKey = apiKey;
        this.timeout = timeout;
    }

    private getAuthHeader(): string {
        return "Bearer " + this.apiKey;
    }

    public sendRequest(path: string): void {
        console.log("GET " + this.baseURL + path);
        console.log("Auth: " + this.getAuthHeader());
    }
}

class UserAPIClient extends APIClient {
    getUsers(): void {
        console.log("Timeout: " + this.timeout); // ✅ protected
        // this.apiKey  // ❌ private — Error!
    }
}

201 - Page Object Model

201_PageObjectModel.ts Protected in POM

Using protected in a real Page Object Model: BasePage's baseURL and navigate() are protected — available to child pages but hidden from external code.

class BasePage {
    protected baseURL: string;

    constructor(url: string) {
        this.baseURL = url;
    }
    protected navigate(path: string): void {
        console.log("Navigating to: " + this.baseURL + path);
    }
}

class LoginPage extends BasePage {
    constructor() { super("https://app.staging.com"); }

    login(user: string): void {
        this.navigate("/login"); // ✅ protected access
        console.log("Typing " + user);
    }
}

202 - Readonly

202_READONLY.ts readonly Modifier

readonly properties can only be set in the constructor — never changed afterward. Perfect for configuration values that must stay constant throughout the test run.

class PlaywrightConfig {
    readonly baseURL: string;
    readonly timeout: number;
    readonly retries: number;

    constructor(url: string, timeout: number, retries: number) {
        this.baseURL = url;
        this.timeout = timeout;
        this.retries = retries;
    }
    showConfig(): void {
        console.log("URL: " + this.baseURL);
        console.log("Timeout: " + this.timeout + "ms");
    }
}

let config = new PlaywrightConfig("https://staging.app.com", 30000, 2);
// config.baseURL = "new"; // ❌ Error: readonly!

203 - Abstract Class

203_Abstract_Class.ts abstract

Abstract classes can't be instantiated — they're templates that force child classes to implement specific methods. abstract methods have no body; each child must provide its own implementation.

abstract class BaseTest {
    protected testName: string;
    constructor(testName: string) {
        this.testName = testName;
    }

    abstract setup(): void;
    abstract execute(): void;
    abstract teardown(): void;
}

class UITest extends BaseTest {
    setup(): void { console.log("  Setup: launch browser"); }
    execute(): void { console.log("  Execute: click, fill forms"); }
    teardown(): void { console.log("  Teardown: close browser"); }
}

// let test = new BaseTest(); // ❌ Cannot instantiate abstract!
let test = new UITest("Login"); // ✅

204 - Type Assertion (as)

204_As_Alias.ts / 204_AS_Part2.ts as Keyword

Type assertion (as) tells TypeScript to treat a value as a specific type. Useful when you know the shape of unknown data (like API responses) but TypeScript doesn't.

let rawResponse: unknown = {
    status: 200,
    body: { user: "admin", role: "tester" }
};

interface UserResponse {
    status: number;
    body: { user: string; role: string };
}

let response = rawResponse as UserResponse;
console.log("Status:", response.status); // 200
console.log("User:", response.body.user);   // "admin"

205 - Override Keyword

205_Override.ts override

TypeScript's override keyword explicitly marks a method as overriding a parent method. If the parent method doesn't exist, TypeScript catches the mistake at compile time.

class BaseTest {
    setup(): void { console.log("[BASE] Open browser"); }
    teardown(): void { console.log("[BASE] Close browser"); }
}

class LoginTest extends BaseTest {
    override setup(): void {
        console.log("[LoginTest] Open browser");
        console.log("[LoginTest] Maximize");
    }
}

class APITest extends BaseTest {
    override setup(): void {
        console.log("[APITest] Init HTTP client");
    }
}

206 - Override Part 2

206_Override.ts Override Pattern

Another override example showing a Father/Son relationship where the child class provides its own implementation of the home() method.

class Father {
    home(): void {
        console.log("2BHK");
    }
}

class Pramod extends Father {
    home(): void {
        console.log("3BHK");
    }
}

let pramod = new Pramod();
pramod.home(); // "3BHK" — child's version
