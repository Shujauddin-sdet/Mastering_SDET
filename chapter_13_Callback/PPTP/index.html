Chapter 13: Callback

Understanding callbacks — passing functions as arguments, synchronous vs asynchronous callbacks, and the infamous callback hell problem.

126 - Callback Basics

126_Callback.js Callbacks

A callback is a function passed as an argument to another function. Demonstrates three ways to pass callbacks: named function, anonymous function, and arrow function. This is the foundation of Playwright's test() API.

function placeOrder(item, callback) {
    console.log("Placing order");
    callback();
}

// Way 1: Named function
placeOrder("Burger", print);

// Way 2: Anonymous function
placeOrder("Burger", function() {
    console.log("Anonymous callback!");
});

// Way 3: Arrow function
placeOrder("Burger", () => {
    console.log("Arrow callback!");
});

127 - Sync Callback

127_Sync_Callback.js Synchronous

Synchronous callbacks execute immediately and block the next line until they finish. forEach() is a classic example — it completes all iterations before moving on.

let testResults = ["PASS", "FAIL", "PASS", "SKIP"];

testResults.forEach(function(result, index) {
    console.log("Test" + index + " -> " + result);
});

// "All done" prints LAST because forEach is synchronous
// — it finishes all 4 iterations first.

128 - Async Callback

128_Async_Callback.js Asynchronous

Asynchronous callbacks are scheduled to run later (e.g., after a timer or network call). setTimeout() demonstrates this: the callback fires after the delay, while the rest of the code continues executing immediately.

console.log("Test 1: started");

setTimeout(function() {
    console.log("Test 2: API response received!");
}, 2000);

console.log("Test 3: Moving to next");

// Output order: Test 1 → Test 3 → Test 2 (after 2s)

129 - Callback Hell

129_Callback_hell.js Nesting Problem

When multiple async operations depend on each other, callbacks nest deeper and deeper — creating the "Pyramid of Doom." This real QA scenario simulates an E2E login flow with nested setTimeout() callbacks.

function openBrowser(callback) {
    setTimeout(function() {
        console.log("Step 1 - browser starting...");
        callback();
    }, 500);
}

function goToLoginPage(callback) {
    setTimeout(function() {
        console.log("Step 2: Login page loaded");
        callback();
    }, 500);
}

// Nested callbacks = Callback Hell!
openBrowser(function() {
    goToLoginPage(function() {
        // deeper and deeper...
    });
});

130 - Callback Exercise

130_Call_Ex01_.js Practice

A simple callback exercise: a greetTester() function accepts a name and a callback. The callback is invoked after the greeting, showing how callbacks extend function behavior.

function greetTester(name, callback) {
    console.log("Welcome, " + name);
    callback();
}

greetTester("Dev", function() {
    console.log("Let's start testing!");
});

131 - Callback Return

131_Callback_Return.js Return Values

Callbacks can also return values. Here a calculate() function takes an operation callback and returns its result — a pattern used in array methods like .map() and .filter().

function calculate(a, b, operation) {
    return operation(a, b);
}

let sum = calculate(10, 5, function(x, y) {
    return x + y;
});

console.log(sum); // 15

132 - Pyramid of Doom

132_Py_of_DON.js Sequential Steps

A sync version of the Pyramid of Doom pattern — chaining sequential steps (open browser → navigate → click) using callbacks. This motivates why Promises and async/await were invented.

function step1(callback) {
    console.log("Open browser");
    callback();
}

function step2(callback) {
    console.log("Navigate to page");
    callback();
}

function step3(callback) {
    console.log("Click button");
    callback();
}

// Pyramid of Doom
step1(function() {
    step2(function() {
        step3(function() {
            console.log("Done!");
        });
    });
});
